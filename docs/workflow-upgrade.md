# IDE workflow upgrade

The twenty-item review is implemented on `codex/ide-workflow-upgrade`, including the prompt recovery changes from merged PR #258, in an isolated worktree. The original checkout and its index are preserved. The table describes delivered behavior and its practical limits; a passing fixture test does not establish that an external account or service is configured correctly.

| Item | Delivered behavior | Validation and limits |
|---|---|---|
| 1. Multimodal specialists | Validated image blocks reach native provider serialization and ACP adapters that advertise image support. Unsupported images fail before context reads, persistence or dispatch. | ACP image-capability, native serialization and invalid-image lifecycle regressions. Chat accepts up to 10 images/5 MiB decoded; the core adapter additionally enforces a 24 MiB encoded cap. Real provider accounts were not exercised. |
| 2. Specialist Plan mode | Native Plan requests expose no tools. ACP Plan requires the advertised mode, rejects mutation approvals and stops reported mutation calls or mode changes. | Native Plan/image and ACP mode/permission fixtures. This enforces the adapter protocol; it is not an OS sandbox around an external executable. |
| 3. Board ACP routes | Board chat uses the selected specialist's configured route. Textual ACP Board proposals become validated host actions, with conversation ownership and cancellation checks. Multiple proposals are confirmed and applied in order against fresh board revisions; all registered specialists are available for assignment. Reassignment commits to the owning pending execution plan before the Board updates, checks the displayed revision and retains each task’s scope access. Refresh recovers current plan/task identities for older Board snapshots. | Board proposal, dependency and conversation-lifecycle tests, plus browser action dispatch. Rejected proposals do not block the queue, and switching conversations invalidates old proposals. Arbitrary prose cannot execute a Board action; no real cloud-backed Board conversation was run. |
| 4. Durable history | Local storage uses immutable 100-message pages and atomic manifests, with migration, body search, workspace filters, pinning, archive and recoverable Trash. Older 50-conversation/500-message retention caps are removed. | Storage migration/retry, paging, independent-store discovery and history browser regressions. Damaged records are preserved with a recovery warning while healthy records remain available. Search reads a text-only index asynchronously, cancels obsolete queries and debounces typing; legacy image-page indexing runs in a worker. Non-file hosts retain the Memento fallback. |
| 5. Verified updates | Stable/preview channels, explicit verified installer downloads and earlier-installer recovery are available in the command palette. Stable release staging requires notarized Developer ID macOS builds and Authenticode Windows builds. | Release staging and installer manifest tests reject channel, target, origin, size, digest and signing mismatches. Downloading/opening are separate actions; no release was published, installer run or signature verified using production credentials. |
| 6. ACP recovery | Settled sessions load when supported. Stale/unsupported sessions receive bounded host transcript context in a new session. Interrupted prompts are never automatically replayed; permanent deletion removes host recovery records. | Restart, session-loading, interrupted-turn, transcript-fallback and deletion fixtures. Recovery retains up to 256 KiB of recent text per route; raw images/tool inputs are excluded. Remote adapter state remains adapter-owned. |
| 7. Context inspector | Preview and send share an explicit context manifest. Each source can be excluded before resolution, preview requests are correlated, and an unchanged preview is reused for the next request. | Context budget, exclusion, snapshot reuse and stale-conversation/request tests; 400 px browser screenshots. At most 32 sources, 40,000 characters per source and 120,000 combined. Images and runtime system instructions/tool results are outside this text preview. |
| 8. Follow-up queue | Queue, reorder, edit, remove, pause/resume and interrupt/redirect work per conversation. The host reserves turns before dispatch; failed pre-persistence drafts are retained, and acknowledgements cannot erase a newer draft. | Queue ownership/capacity/cancellation/redirect-race tests and request-correlation browser scenarios. Ten waiting drafts are accepted; recovering an already accepted in-flight draft may retain one additional draft. Queues remain window-local. |
| 9. Conversation branches | A response action branches through its exact message index and records its parent/checkpoint association. Linked checkpoints remain retained, and stale links are represented as unlinked. | Branch/store and checkpoint-retention tests; response-action browser checks. Selecting a branch never restores files automatically; restoration is a separate explicit operation. |
| 10. Checkpoints outside Git | Scratch folders receive content-addressed file snapshots, change previews, confirmation rechecks and recovery snapshots for failed restores. Git workspaces retain their existing checkpoint backend. | Real temporary-folder restore, cancellation, edit-race, symlink, workspace identity and file/directory transition tests. Limits: 50 MiB/10,000 files; dependency/VCS directories excluded; symlinks refused. |
| 11. Project integration profiles | Workspace-owned profiles select skills/plugins/MCP IDs and snapshot all specialist model/ACP routes. Profiles can be activated, recaptured or replaced with global configuration. Source changes refresh, and duplicate origins remain inspectable. | Profile validation/capture, catalog selection, source-disable and skill-resource tests. Profiles never import credentials or bypass workspace/server trust, and discovered MCP servers do not start merely because they were found. |
| 12. Extension gallery | The standard Extensions view uses Eclipse Open VSX's VS Code-compatible gallery endpoints and retains native VSIX installation/update controls. | Configuration checked against Open VSX's official integration documentation; extension build passes. No extension was installed during validation. Microsoft-only or unavailable extensions are not made compatible by the gallery change. |
| 13. Unsaved code intelligence | Dirty editor buffers and LSP outlines overlay embedded graph outline/search results in memory. Save, close, disable and workspace changes clear them; stale document versions/revisions are rejected. | Four overlay tests, including a real MCP subprocess notification/query/clear exchange, plus watcher regressions. At most 32 documents/256 KiB each/2 MiB total; no disk persistence or remote embeddings. Unsaved text matches are explicitly not vector similarity; HTTP backends are skipped. |
| 14. Symbol impact | LSP incoming-call hierarchy carries real caller lines and intermediate paths. Host-issued navigation identities preserve separate caller lines within the same file and reject clicks from an outdated graph. Actual caller edges into test files are grouped as affected tests; unsupported languages show saved file-dependency paths instead. | Language-impact, host navigation, browser keyboard/pointer and native graph path tests. Missing or invalid lines open the file without selecting a line. Three hops/80 nodes/time limits apply. This reports dependency evidence, not measured test coverage or guaranteed language-wide completeness. |
| 15. Dependency editor | Board dependencies can be edited visually with cycle detection, blockers and scheduling waves. Applying a preview validates the plan revision and rejects running or stale plans. | Core plan ownership, Board dependency/proposal and browser cycle/preview/apply tests. Edits use existing plan semantics and do not invent new tasks or claim that a blocked task ran. |
| 16. Council evidence | Review citations must match the reviewed revision, old/new line coordinates and contiguous diff-hunk text. Fabricated excerpts remain visible as failed stages and cannot satisfy quorum. | Citation/hunk fixtures and Council failure/quorum tests. Matching evidence verifies a citation's provenance, not the correctness of a review finding. |
| 17. Usage and budgets | ACP context occupancy and cumulative cost retain their protocol meaning; unmetered requests stay visible. Request, runtime and tool-call budgets work independently of billed-token availability. Native estimates use the rates of the models actually requested. Concurrent calls share host counters, so per-response deltas are approximate during overlapping work. | Session-budget and ACP usage/tool-limit fixtures. No fabricated billed input/output tokens, subscription invoices or unknown pricing; provider billing remains authoritative. |
| 18. Service diagnostics | One command aggregates observed graph/MCP/background/health states and exposes targeted log, restart, reindex, reconnect and ACP-diagnosis actions. Unchanged but closed MCP connections can recover without replacing ready connections. | Stale/unknown health aggregation and crashed-connection recovery tests. ACP handshakes require an explicit trusted action. A ready connection does not assert that every tool invocation or remote service has passed. |
| 19. Feedback and evaluation | Helpful/not-helpful votes persist on exact response indices. An explicit command opens a local JSON evaluation report with rated text, route/outcome and available measurements. | Feedback ownership, export/redaction and eviction/replay browser tests. Export contains selected prompt/response text for review; no automatic upload, images, correctness score, coverage claim or invented measurements. |
| 20. Typed chat and bounded rendering | Typed response actions, queue/context/provider controls and a typed timeline model support keyboard use. Chat initially mounts 200 messages and keeps at most 300, with older/newer/latest navigation and pinned live turns. | Three timeline model tests and browser tests for eviction, live Markdown, scroll position, prompt reuse, votes, indices and checkpoints. Large Boards page initial columns. Conversation data remains available off-DOM; this does not impose a storage retention cap. |

The additional Provider Finder inventories coding software and configured account catalogs, offers a searchable picker beyond the first 100 rendered entries, and can explicitly test one model's synthetic tool support. Installation, sign-in-file presence, catalog access and observed inference support are different statuses. The extension automatically reads model lists from running Ollama and LM Studio servers; users can disable this. Discovery never starts a server or loads a model. See [provider discovery contracts and limits](evaluations/provider-discovery-2026-09-08.md) and [platform behavior](platform-capabilities.md).

The core test command bounds file concurrency to two: an unbounded run under simultaneous build/browser load hit a filesystem-workflow timeout, while the isolated test and complete bounded run passed. Release staging, actual MCP subprocess exchange, filesystem recovery and HTTP/ACP protocol fixtures run locally in disposable locations. The browser suite renders the actual shipped webview HTML/CSS/JavaScript in Chrome with an offline host fixture, including sidebar-width screenshots. An isolated installed-host extension activation was observed, but native CDP interaction stalled; a complete native live-agent visual walkthrough is not claimed.

ACP selection accepts 512-character raw model IDs independently of the adapter namespace. Checkpoint indexing uses the same native canonical path as snapshot capture, including Windows path casing. Installer downloads use an explicit stream reader compatible with the packaging compiler, cancel on failure and release their reader. CI checks the extension with that native compiler before running regressions. Local follow-up validation passed: mandatory extension compilation, native extension and test TypeScript checks, core/CLI builds, 190 core tests, 488 extension tests, 49 browser scenarios and 11 updater/release tests. Additional review fixes replace complete provider/ACP catalogs within their own scope, retire missing models without reviving them from older sessions, and preserve cached routes after incomplete or failed refreshes. The picker uses maps for provider-controlled IDs, removes stale metadata, and preserves unavailable saved selections rather than silently changing providers. Deleting the final surviving conversation branch releases retained filesystem snapshots and Git checkpoint references. File capture checks opened-descriptor identity around bounded reads. Every supported release suffix is classified as preview, and update candidates are verified against the installed build before any notification. Local review validation passed 355 core tests, 649 extension tests, 63 browser scenarios, 26 release-policy/packaging tests, 28 CLI tests, 14 ACP service tests, eight shared-auth tests, nine overlay/impact tests and three installed-runtime/retrieval fixtures (1155 total). The changed extension passed regular test TypeScript, native `tsgo`, the bundle build and mandatory `gulp compile-extensions` checks. A focused browser recheck confirms incomplete/disabled catalogs retain saved selections and a completed catalog removal cannot silently switch providers; the notice was visually checked at 400 px. Review commit `017471fc552` passed every GitHub build, package, CodeQL and four-platform native installer job. Editor overlays accept flat SymbolInformation, DocumentSymbol and hybrid API results, retaining nested symbols and UTF-8 offsets. Orchestrator exceptions, runtime limits and failed/blocked approvals now produce explicit failed outcomes through chat persistence and feedback export. Partial responses survive failures; user cancellation remains distinct. Approve/reject commands enforce conversation ownership, and a cancelled approval cannot clear a newer plan or borrow its context. CLI planning failures exit unsuccessfully without a completion event. These paths have command-to-MCP, real-orchestrator-to-chat/export, ownership and cancellation regressions.

The final board/history follow-up serializes proposal confirmation and validates assignees against the registered roster. History searches use cancellable, asynchronous text-index reads, a 250 ms typing debounce and stale-response guards. Derived caches are optional and follow the message pages' retention leases; cache-write failure cannot prevent an authoritative history save. Legacy image pages are indexed in a bounded worker. Legacy pages over 64 MiB remain preserved and produce a recovery notice until resaved with the new text index. Regression tests cover queue ownership, Unicode and part boundaries, exact result totals, legacy indexing/cancellation, storage failures, corrupt caches/pages and concurrent cleanup.

CI exposed an inconsistent dependency-editor draft during task switches. Selection, dependencies and revision now update together without resetting focused controls; repeated switching, host revisions and task removal have browser regressions. Forced provider refreshes queue a fresh scan behind active discovery, coalescing bursts while retaining cancellation and local-discovery options. Normal installer updates require a strictly higher version and rollback requires a strictly lower version before metadata requests. Publication dates order choices independently of the installed source date, so backfilled releases remain eligible in the correct direction.

Complete configured Foundry/Bedrock mappings and Z.AI model lists, including empty inventories, replace their own provider inventories and reconcile cached routes at startup. Invalid, unreadable or oversized mappings preserve the last usable inventory; removed saved selections stay visible with sending disabled. Direct chat advertises tools only for models with confirmed support, while text and supported images still work for newly discovered models. Unsolicited tool calls are rejected before approval or execution. Real HTTP payload, configuration/restart and browser regressions cover these paths.

Foundry catalogs preserve the configured model family separately from deployment names and display labels. Known reasoning families send `max_completion_tokens`; classic and unknown custom families retain `max_tokens`, following [Microsoft's request contract](https://learn.microsoft.com/en-ca/azure/foundry/openai/how-to/reasoning). A custom reasoning deployment should use a known semantic mapping key such as `foundry-gpt-5`. Together AI and LM Studio inference accept the same environment aliases and credential precedence as discovery, including `TOGETHERAI_API_KEY` and `LM_API_TOKEN`.

Permanent deletion serializes writes and awaits ACP/checkpoint cleanup after the deletion commits. File-backed history adds process-owned commit locks and permanent tombstones outside transcript folders: stale windows, queued writes and migration cannot recreate a deleted ID. Pre-commit failures retain the Trash entry; failed physical reclamation after commit leaves the conversation deleted and retries file cleanup later. Other windows observe tombstones, close affected chats and replay local cleanup, including after restart. Cleanup remains attached to the write queue through UI disposal, so shutdown waits for it. Non-file Memento hosts retain the existing local queue and fallback behavior. Release packaging signs and notarizes the application and final DMG separately when credentials are configured; manifest status comes from validated helper outcomes, including accepted submissions and successful stapling/validation. Seventeen new subprocess packaging regressions cover failures, key cleanup, final artifact hashes, unsigned previews and Windows/Linux compatibility. A real local preview DMG passed creation, ad-hoc signing and signature verification; no production notarization was performed.

ACP recovery and checkpoint cleanup failures remain visible to the history store after both operations settle. Completion is reported only after successful cleanup; a later explicit flush or lifecycle scan retries failed work. Concurrent drains share an attempt, and repeated failures do not trigger an immediate retry loop.

Conversation saves compare the session's loaded manifest revision under the cross-process commit lock. A stale window or second chat surface cannot overwrite newer stored turns. Each session keeps its own write token, including sessions opened before a pending save completes; listing history and reading individual messages do not advance that token. Conflicts preserve the stored transcript and leave the local copy unsaved for recovery. The check covers metadata as well as messages, so concurrent metadata edits can conservatively produce a conflict instead of silently merging changes. A global history flush continues to report unresolved conflicts; a branch can be persisted while its action still reports an older source conflict. Export remains available for the local copy.

Activation no longer waits for legacy history to finish migrating to disk before registering the remaining IDE services and views. The existing synchronous in-memory seeding still runs; that pending copy remains accessible, and edits made during migration retain their write ownership. Migration settlement refreshes already registered history views, while disposal suppresses notifications without abandoning queued writes or recovery data. A successful cleanup retry clears its earlier queue failure; unfinished migration finalization remains reported until recovery.

Failed checkpoint indexing releases only the new filesystem snapshot or Git reference, preserving existing and shared snapshots and the original persistence error. An uncertain durable commit preserves its payload for recovery. A failed branch save removes that branch's checkpoint attachment and retains an explicitly unlinked recovery transcript. Recovery failures remain visible; they do not turn a failed branch into a successful one.

Checkpoint metadata now uses a shared file-backed index for each canonical workspace. Process-owned locks serialize updates against the current durable file, so two windows cannot replace each other's captures with stale Memento arrays. Legacy indexes remain read-only migration sources. A global deletion journal and shared metadata lock prevent late captures and imports from recreating permanently deleted conversations. Cleanup discovers every stored workspace, including legacy IDE/CLI inventories, without reopening the original file workspace. Payload descriptors remain durable until removal succeeds, so failures retry after restart. Inaccessible Git repositories retain pending reference cleanup until they become accessible. Temporary branch detachment preserves the recovered conversation and permits future checkpoints. Active restore pins protect targets and recovery snapshots from other windows' pruning and deletion, and filesystem restores serialize across processes. Damaged metadata remains preserved and blocks checkpoint changes until recovery. Chat/sidebar initialization, history switching and text branching remain available; checkpoint controls clear only for the matching conversation and return when the index is repaired.

Git and filesystem restores persist their recovery checkpoint before changing workspace files. If that write fails, restoration stops with the original files intact. Files are rechecked after persistence, and an indexed recovery snapshot stays reachable when later validation or cleanup fails. Temporary retention protects an active restore's target and recovery without discarding concurrent captures. The native installer matrix runs shared-history ownership, cross-process revision, checkpoint recovery, background migration and branch-recovery regressions on Windows, Linux and both macOS architectures.

One-shot ACP Council stages opt out of host session recovery because their durable results belong to Council reports. Anonymous specialist calls also skip recovery when their generated ID cannot be reused by a caller. These turns neither read nor write recovery transcripts, and their workers cannot reuse a durable chat session. Explicit conversation and task IDs retain their existing recovery keys and restart behavior.

ACP model selection checks the complete validated advertisement for both new and recovered sessions. Discovery exposes at most 500 unique models, so a valid explicitly configured model beyond that display limit remains usable. Invalid rows and duplicates cannot crowd valid models out of the visible catalog.

Optional ACP recovery-storage failures now produce sanitized diagnostics while chat continues. Failed writes retain bounded current-host context (at most 32 records of 512 KiB encoded payload each); durable crash recovery is unavailable during an outage. After fallback overflow, stored records are treated conservatively as interrupted for that store lifetime. The standalone ACP service includes the same regenerated runtime. Detailed impact results retain alternate dependency edges using acyclic witnesses, query each admitted file once and report truncation at 200 files, 1000 paths or 10,000 inspected adjacency entries. Real MCP and installed-native diamond fixtures cover the evidence.

HTTP model catalogs now retire their routes and picker metadata when every applicable credential source confirms absence. Removing one source retains the catalog if another credential remains. Storage, configuration, broker and catalog failures preserve the last inventory with sanitized diagnostics; startup refresh rechecks credentials even inside a persisted cache lifetime. OAuth refresh failures retain credentials for retry unless a bounded error response explicitly confirms `invalid_grant`, following [RFC 6749 section 5.2](https://www.rfc-editor.org/rfc/rfc6749#section-5.2). Saved conversations retain unavailable model selections with sending disabled.

Orchestrator graph queries and MCP initialization/tool waits now use the turn deadline and cancellation signal. Late responses cannot start a specialist or resume a cancelled turn; shared connection startup remains available to other callers. Workspace provider settings follow their allowed scopes, with authenticated local catalog requests restricted to the endpoint configured in User settings.

LM Studio inference also binds API keys and custom headers to the full endpoint configured in User settings, including direct requests that have never scanned a catalog. Live scope inspection catches subsequent endpoint changes. Credential-bearing requests reject redirects and use one captured header set; anonymous workspace servers remain available.

Response actions now carry a host-issued reference and the actual saved assistant index. Local commands, rejected sends and empty or cancelled turns can leave provisional rows; visual timeline positions are therefore kept separate from persisted message identities. Completion can precede persistence, and acknowledgments retain both submission and conversation ownership. Feedback and branching validate the saved response before acting.

Real configured Act/Plan specialist probes confirm that ACP already enforced its execution budget with a cancellation signal; its one-hour prompt timeout is a secondary transport ceiling, and human approval pauses the execution budget. Optional recovery writes now stop delaying turn completion after deadline, cancellation or shutdown. A prompt that already finished keeps its outcome, while the store preserves write ordering for subsequent turns and permanent deletion.

Production signing and real cloud-account inference remain external validation requirements. This work does not publish a release, install an update, copy another app's credentials, change installed-IDE settings, or execute discovered integrations automatically.

ACP model selections resolve to a registered specialist capable of using the exact advertised adapter and model. Direct-only personas remap when needed; unavailable catalog or adapter combinations fail before hooks, checkpoint capture or transcript writes. Toolbar, slash-command, restored and queued selections share that validation, and host acknowledgements update both model and specialist while ignoring stale draft selections.

Linux CI removes the runner's unused Google Chrome package-source entries before installing Ubuntu build dependencies. This avoids unrelated Chrome repository publication mismatches while retaining the preinstalled browser, required package sources and normal APT integrity checks.

Direct chat rejects fresh or restored image attachments when the selected model lacks confirmed vision support, before hooks, context reads, checkpoints or transcript writes. Tool continuations use the original tool-call IDs and structured results, including provider reasoning content and thought signatures when present. Those provider-only fields stay out of the visible and persisted transcript; cancellation prevents a follow-up request.
