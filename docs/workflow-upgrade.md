# IDE workflow upgrade

The twenty-item review is implemented on `codex/ide-workflow-upgrade`, including the prompt recovery changes from merged PR #258, in an isolated worktree. The original checkout and its index are preserved. The table describes delivered behavior and its practical limits; a passing fixture test does not establish that an external account or service is configured correctly.

| Item | Delivered behavior | Validation and limits |
|---|---|---|
| 1. Multimodal specialists | Validated image blocks reach native provider serialization and ACP adapters that advertise image support. Unsupported images fail before context reads, persistence or dispatch. | ACP image-capability, native serialization and invalid-image lifecycle regressions. Chat accepts up to 10 images/5 MiB decoded; the core adapter additionally enforces a 24 MiB encoded cap. Real provider accounts were not exercised. |
| 2. Specialist Plan mode | Native Plan requests expose no tools. ACP Plan requires the advertised mode, rejects mutation approvals and stops reported mutation calls or mode changes. | Native Plan/image and ACP mode/permission fixtures. This enforces the adapter protocol; it is not an OS sandbox around an external executable. |
| 3. Board ACP routes | Board chat uses the selected specialist's configured route. Textual ACP Board proposals become validated host actions, with conversation ownership and cancellation checks. Multiple proposals are confirmed and applied in order against fresh board revisions; all registered specialists are available for assignment. | Board proposal, dependency and conversation-lifecycle tests, plus browser action dispatch. Rejected proposals do not block the queue, and switching conversations invalidates old proposals. Arbitrary prose cannot execute a Board action; no real cloud-backed Board conversation was run. |
| 4. Durable history | Local storage uses immutable 100-message pages and atomic manifests, with migration, body search, workspace filters, pinning, archive and recoverable Trash. Older 50-conversation/500-message retention caps are removed. | Storage migration/retry, paging, independent-store discovery and history browser regressions. Damaged records are preserved with a recovery warning while healthy records remain available. Search reads a text-only index asynchronously, cancels obsolete queries and debounces typing; legacy image-page indexing runs in a worker. Non-file hosts retain the Memento fallback. |
| 5. Verified updates | Stable/preview channels, explicit verified installer downloads and earlier-installer recovery are available in the command palette. Stable release staging requires notarized Developer ID macOS builds and Authenticode Windows builds. | Release staging and installer manifest tests reject channel, target, origin, size, digest and signing mismatches. Downloading/opening are separate actions; no release was published, installer run or signature verified using production credentials. |
| 6. ACP recovery | Settled sessions load when supported. Stale/unsupported sessions receive bounded host transcript context in a new session. Interrupted prompts are never automatically replayed; permanent deletion removes host recovery records. | Restart, session-loading, interrupted-turn, transcript-fallback and deletion fixtures. Recovery retains up to 256 KiB of recent text per route; raw images/tool inputs are excluded. Remote adapter state remains adapter-owned. |
| 7. Context inspector | Preview and send share an explicit context manifest. Each source can be excluded before resolution, preview requests are correlated, and an unchanged preview is reused for the next request. | Context budget, exclusion, snapshot reuse and stale-conversation/request tests; 400 px browser screenshots. At most 32 sources, 40,000 characters per source and 120,000 combined. Images and runtime system instructions/tool results are outside this text preview. |
| 8. Follow-up queue | Queue, reorder, edit, remove, pause/resume and interrupt/redirect work per conversation. The host reserves turns before dispatch; failed pre-persistence drafts are retained, and acknowledgements cannot erase a newer draft. | Queue ownership/capacity/cancellation/redirect-race tests and request-correlation browser scenarios. Ten waiting drafts are accepted; recovering an already accepted in-flight draft may retain one additional draft. Queues remain window-local. |
| 9. Conversation branches | A response action branches through its exact message index and records its parent/checkpoint association. Linked checkpoints remain retained, and stale links are represented as unlinked. | Branch/store and checkpoint-retention tests; response-action browser checks. Selecting a branch never restores files automatically; restoration is a separate explicit operation. |
| 10. Checkpoints outside Git | Scratch folders receive content-addressed file snapshots, change previews, confirmation rechecks and recovery snapshots for failed restores. Git workspaces retain their existing checkpoint backend. | Real temporary-folder restore, cancellation, edit-race, symlink, workspace identity and file/directory transition tests. Limits: 50 MiB/10,000 files; dependency/VCS directories excluded; symlinks refused. |
| 11. Project integration profiles | Workspace-owned profiles select skills/plugins/MCP IDs and snapshot all specialist model/ACP routes. Profiles can be activated, recaptured or replaced with global configuration. Source changes refresh, and duplicate origins remain inspectable. | Profile validation/capture, catalog selection, source-disable and skill-resource tests. Profiles never import credentials or bypass workspace/server trust, and discovered MCP servers do not start merely because they were found. |
| 12. Extension gallery | The standard Extensions view uses Eclipse Open VSX's VS Code-compatible gallery endpoints and retains native VSIX installation/update controls. | Configuration checked against Open VSX's official integration documentation; extension build passes. No extension was installed during validation. Microsoft-only or unavailable extensions are not made compatible by the gallery change. |
| 13. Unsaved code intelligence | Dirty editor buffers and LSP outlines overlay embedded graph outline/search results in memory. Save, close, disable and workspace changes clear them; stale document versions/revisions are rejected. | Four overlay tests, including a real MCP subprocess notification/query/clear exchange, plus watcher regressions. At most 32 documents/256 KiB each/2 MiB total; no disk persistence or remote embeddings. Unsaved text matches are explicitly not vector similarity; HTTP backends are skipped. |
| 14. Symbol impact | LSP incoming-call hierarchy carries real caller lines and intermediate paths. Actual caller edges into test files are grouped as affected tests; unsupported languages show saved file-dependency paths instead. | Language-impact and native graph path tests. Three hops/80 nodes/time limits apply. This reports dependency evidence, not measured test coverage or guaranteed language-wide completeness. |
| 15. Dependency editor | Board dependencies can be edited visually with cycle detection, blockers and scheduling waves. Applying a preview validates the plan revision and rejects running or stale plans. | Core plan ownership, Board dependency/proposal and browser cycle/preview/apply tests. Edits use existing plan semantics and do not invent new tasks or claim that a blocked task ran. |
| 16. Council evidence | Review citations must match the reviewed revision, old/new line coordinates and contiguous diff-hunk text. Fabricated excerpts remain visible as failed stages and cannot satisfy quorum. | Citation/hunk fixtures and Council failure/quorum tests. Matching evidence verifies a citation's provenance, not the correctness of a review finding. |
| 17. Usage and budgets | ACP context occupancy and cumulative cost retain their protocol meaning; unmetered requests stay visible. Request, runtime and tool-call budgets work independently of billed-token availability. Native estimates use the rates of the models actually requested. Concurrent calls share host counters, so per-response deltas are approximate during overlapping work. | Session-budget and ACP usage/tool-limit fixtures. No fabricated billed input/output tokens, subscription invoices or unknown pricing; provider billing remains authoritative. |
| 18. Service diagnostics | One command aggregates observed graph/MCP/background/health states and exposes targeted log, restart, reindex, reconnect and ACP-diagnosis actions. Unchanged but closed MCP connections can recover without replacing ready connections. | Stale/unknown health aggregation and crashed-connection recovery tests. ACP handshakes require an explicit trusted action. A ready connection does not assert that every tool invocation or remote service has passed. |
| 19. Feedback and evaluation | Helpful/not-helpful votes persist on exact response indices. An explicit command opens a local JSON evaluation report with rated text, route/outcome and available measurements. | Feedback ownership, export/redaction and eviction/replay browser tests. Export contains selected prompt/response text for review; no automatic upload, images, correctness score, coverage claim or invented measurements. |
| 20. Typed chat and bounded rendering | Typed response actions, queue/context/provider controls and a typed timeline model support keyboard use. Chat initially mounts 200 messages and keeps at most 300, with older/newer/latest navigation and pinned live turns. | Three timeline model tests and browser tests for eviction, live Markdown, scroll position, prompt reuse, votes, indices and checkpoints. Large Boards page initial columns. Conversation data remains available off-DOM; this does not impose a storage retention cap. |

The additional Provider Finder inventories coding software and configured account catalogs, offers a searchable picker beyond the first 100 rendered entries, and can explicitly test one model's synthetic tool support. Installation, sign-in-file presence, catalog access and observed inference support are different statuses. The extension automatically reads model lists from running Ollama and LM Studio servers; users can disable this. Discovery never starts a server or loads a model. See [provider discovery contracts and limits](evaluations/provider-discovery-2026-09-08.md) and [platform behavior](platform-capabilities.md).

Final combined validation passed: `gulp compile-extensions`, core/extension/test/Board/webview TypeScript checks, 185 core tests, 474 extension tests, 47 browser scenarios, 7 release staging tests and 4 graph overlay tests. The core test command bounds file concurrency to two: an unbounded run under simultaneous build/browser load hit a filesystem-workflow timeout, while the isolated test and complete bounded run passed. Release staging, actual MCP subprocess exchange, filesystem recovery and HTTP/ACP protocol fixtures run locally in disposable locations. The browser suite renders the actual shipped webview HTML/CSS/JavaScript in Chrome with an offline host fixture, including sidebar-width screenshots. An isolated installed-host extension activation was observed, but native CDP interaction stalled; a complete native live-agent visual walkthrough is not claimed.

PR #259 review follow-up: migration recomputes counts from actual messages and initialization failures leave chat available with a recovery warning. Obsolete immutable pages are reclaimed after publication, retaining leases for concurrent readers and writers; read-only, full and quota-limited storage can still read complete history. ACP selection accepts 512-character raw model IDs independently of the adapter namespace. Checkpoint indexing uses the same native canonical path as snapshot capture, including Windows path casing. Installer downloads use an explicit stream reader compatible with the packaging compiler, cancel on failure and release their reader. CI checks the extension with that native compiler before running regressions. Local follow-up validation passed: mandatory extension compilation, native extension and test TypeScript checks, core/CLI builds, 190 core tests, 488 extension tests, 49 browser scenarios and 11 updater/release tests. Browser regressions include assistant-first history pages; storage regressions include a reader overlapping a separate writer process.

The native installer matrix subsequently passed on macOS ARM, macOS Intel, Linux and Windows, including fresh installation checks. The broader agent harness exposed a separate ACP service packaging omission: its flat four-file copy excluded the new model catalog dependency. Staging now preserves the complete minimal ACP compilation tree, checks exact generated contents and loads the runtime from the service package; the Docker build checks the same import. Follow-up local checks passed all 14 ACP service tests, eight shared-auth tests and two installed-runtime/retrieval fixtures, with no stale or cross-workspace retrieval results. A standalone Linux ARM Docker build passed compilation and the guarded runtime import with fresh locked dependencies.

Additional review fixes replace complete provider/ACP catalogs within their own scope, retire missing models without reviving them from older sessions, and preserve cached routes after incomplete or failed refreshes. The picker uses maps for provider-controlled IDs, removes stale metadata, and preserves unavailable saved selections rather than silently changing providers. Deleting the final surviving conversation branch releases retained filesystem snapshots and Git checkpoint references. File capture checks opened-descriptor identity around bounded reads. Every supported release suffix is classified as preview, and update candidates are verified against the installed build before any notification. See the [security review](evaluations/pr259-security-review.md) for the two intentional provider-credential flows that remain documented CodeQL findings.

Local review validation passed 209 core tests, 530 extension tests, 51 browser scenarios, nine release-policy tests, 26 CLI tests, 14 ACP service tests, eight shared-auth tests and two installed-runtime/retrieval fixtures (849 total). The changed extension passed regular test TypeScript, native `tsgo`, the bundle build and mandatory `gulp compile-extensions` checks. A focused browser recheck confirms incomplete/disabled catalogs retain saved selections and a completed catalog removal cannot silently switch providers; the notice was visually checked at 400 px. Review commit `4baa6856bdf` passed every GitHub build, package, CodeQL and four-platform native installer job. CodeQL marked the regex, model-property injection and file-race alerts fixed on the PR.

Editor overlays accept flat SymbolInformation, DocumentSymbol and hybrid API results, retaining nested symbols and UTF-8 offsets. Orchestrator exceptions, runtime limits and failed/blocked approvals now produce explicit failed outcomes through chat persistence and feedback export. Partial responses survive failures; user cancellation remains distinct. Approve/reject commands enforce conversation ownership, and a cancelled approval cannot clear a newer plan or borrow its context. CLI planning failures exit unsuccessfully without a completion event. These paths have command-to-MCP, real-orchestrator-to-chat/export, ownership and cancellation regressions.

The final board/history follow-up serializes proposal confirmation and validates assignees against the registered roster. History searches use cancellable, asynchronous text-index reads, a 250 ms typing debounce and stale-response guards. Derived caches are optional and follow the message pages' retention leases; cache-write failure cannot prevent an authoritative history save. Legacy image pages are indexed in a bounded worker. Legacy pages over 64 MiB remain preserved and produce a recovery notice until resaved with the new text index. Regression tests cover queue ownership, Unicode and part boundaries, exact result totals, legacy indexing/cancellation, storage failures, corrupt caches/pages and concurrent cleanup.

Production signing and real cloud-account inference remain external validation requirements. This work does not publish a release, install an update, copy another app's credentials, change installed-IDE settings, or execute discovered integrations automatically.
