# PR #255 review follow-up — 8 September 2026

Reviewed all 26 inline comments on [PR #255](https://github.com/CodeHalwell/Son-Of-Anton/pull/255): seven behavioral findings and 19 CodeQL annotations. This follow-up fixes all seven behavioral findings, hardens nine runtime cases flagged by CodeQL, and cleans up three test annotations. Seven remaining CodeQL warnings are assessed below as false positives or intended behavior; no alerts were dismissed, suppressed, or marked resolved through the GitHub API.

These changes follow the published `ide-v1.112.0` preview. That existing release was built from `fdbc014044c549c9b45c57cc9ff3b0972490e053` and does **not** contain this follow-up.

## Warnings requiring reviewer disposition

These are source-level assessments, not a claim that a fresh CodeQL findings check is green. No query configuration or suppression was added.

| Alerts | Evidence and assessment |
| --- | --- |
| [762 — password hashing](https://github.com/CodeHalwell/Son-Of-Anton/security/code-scanning/762) | `ProtectedSecretStore.file(key)` hashes a **storage identifier**, such as `sota.secrets.anthropicApiKey`, to obtain a stable DPAPI filename. `commands/auth.ts` obtains identifiers through `apiKeySecretKeys`; their literal definitions are in `credentialDetection.ts`. Credential values are protected through DPAPI, Keychain, or Secret Service. A clarifying comment was added; changing this filename derivation would break access to existing credentials without improving password storage. |
| [761 — checkpoint path injection](https://github.com/CodeHalwell/Son-Of-Anton/security/code-scanning/761) | `assertSafePathSegment` rejects separators, NUL, empty values, and parent references; `sessionPath` additionally checks resolved containment. Snapshot hashes are restricted to 64 hexadecimal characters, and loaded snapshot content is checked against its hash. The reported HTTP-parameter-to-path flow passes through these application guards. All eight checkpoint tests, including traversal regressions, pass. |
| [776](https://github.com/CodeHalwell/Son-Of-Anton/security/code-scanning/776), [777](https://github.com/CodeHalwell/Son-Of-Anton/security/code-scanning/777), [778](https://github.com/CodeHalwell/Son-Of-Anton/security/code-scanning/778), [779](https://github.com/CodeHalwell/Son-Of-Anton/security/code-scanning/779) — configuration in provider requests | The model router intentionally reads its configured routes and failover settings, resolves a configured provider, and uses that provider's endpoint, model, and authentication data in its API request. The flagged sources are the router configuration reads in `services/model-router/src/server.ts`, not a request-supplied arbitrary filename. Operator-controlled configuration is part of the trust boundary; these flows implement configurable providers. |
| [765 — package smoke launcher](https://github.com/CodeHalwell/Son-Of-Anton/security/code-scanning/765) | This test runs the vendor launchers from its own extracted package fixture. It replaces `SOTA_CACHE_DIR` with a fresh temporary fixture path and uses the existing `crossSpawn` launcher handling. The inherited process environment belongs to the test runner; the flow is not from an untrusted HTTP or agent request into a shell command. |
