## 2024-06-25 - Fix keyboard focus for disabled custom button components
**Learning:** When disabling a custom UI component acting as a button (e.g., an element with `role="button"`), applying CSS pointer-events or adding an `aria-disabled` property is insufficient for accessibility. The element will still receive keyboard focus unless its `tabindex` is explicitly set to `-1`. Furthermore, event handlers registered on the element (like Enter/Space keydowns) will still trigger if the component is focused somehow, requiring explicit logic to bypass the event execution when disabled.
**Action:** When a custom element mimicking a button is disabled, always update its `tabindex` to `-1` to remove it from the focus order, and ensure click/keydown event handlers include a condition to skip execution when the component's internal disabled state is active.
