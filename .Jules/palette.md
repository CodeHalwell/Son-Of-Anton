## 2024-05-24 - Accessibility improvements for non-native interactive elements
**Learning:** In the Issue Reporter component (`src/vs/workbench/contrib/issue/browser/baseIssueReporterService.ts` and `issueReporterPage.ts`), there are non-native elements (`<span>` and `<a>`) that are used as buttons (`role="button"` and `tabIndex=0`). These elements have JavaScript event listeners for click and keydown to act like buttons. However, when these custom buttons need to be "disabled" (e.g. `disableExtensions` button when extensions are already disabled), the code attempts to disable them using `element.disabled = true`. This is incorrect because the `disabled` attribute has no effect on non-native button elements (like `<span>` or `<a>`). The element remains keyboard focusable and its event handlers are still triggered.
**Action:** When disabling a custom element with `role="button"`, do not use the `.disabled` property. Instead, use `element.setAttribute('aria-disabled', 'true')` to convey the disabled state to screen readers. In addition, you must remove the `tabindex` or set it to `-1` to remove it from the focus order, and you must add logic in the event listeners to ignore clicks/keypresses when the element is visually/semantically disabled, or use CSS `pointer-events: none;`.
