## 2024-05-15 - Missing ARIA labels on dynamic toggle links
**Learning:** Found an accessibility issue pattern specific to the Issue Reporter component. Several `<a>` elements acting as buttons to toggle detailed system information (e.g., showing/hiding process info, workspace metadata) use generic visual text ("show" / "hide") but lack stable, descriptive `aria-label`s. Screen reader users would just hear "show, button" without context of *what* is being shown, especially since they are grouped within parenthesis text nodes rather than being structurally associated with the field labels.
**Action:** When implementing custom toggle buttons or links with dynamic visual text (e.g., swapping between "show" and "hide"), always apply a stable, descriptive `aria-label` (e.g., "Toggle process info") to the element so context is preserved for screen readers regardless of the visual state.
